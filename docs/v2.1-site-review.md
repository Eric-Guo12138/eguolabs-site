## Improvements

The navy/teal hero, headline, original diagram, navigation architecture, founder presentation and three illustrated service areas remain. The hero copy is shorter, technical labels are larger, linked junctions illuminate with the selected route, and record selection is synchronised with the new deliverables explorer.

New deliverables explorer:

- Pipework schedule: an original schematic, selected-record summary and semantic table with diameter, centreline length, connection context, drawing reference and review status. Diagram controls and table rows share selection.
- Excel / CSV output: independent Standard Schedule and Customer Format tabs change column names, column order and row grouping. Mapping examples, optional fields and review flags explain customisation. This is a preview; no non-working download button is offered.
- Review & Exceptions: the P-03 size and route questions retain their source reference and estimator note. Teal, amber and neutral metadata convey distinct states without alarm styling.

The five-dimension customisation explorer covers inputs, rules, outputs, review process and internal tools. Each selection has its own explanation and concrete example preview.

The former four-stage technical workflow and separate engagement process are consolidated into three customer-facing stages using the existing accessible tab pattern: Tell Us the Problem, Explore the Approach and Define a Focused Project. Engineering responsibility is now one compact section.

Primary discovery CTAs scroll to contact. Visitors can optionally select a topic and describe a task; the contact CTA prepares an encoded mailto draft locally. The address and plain Email Eric links remain visible. There is no backend submission, success claim, upload request, tracking or persistent storage. Privacy copy explains the local draft behaviour.

Browser automation repeatedly timed out before returning a V2.1 page snapshot. One connection attempt was also prevented because automatic approval review could not complete due to a usage limit. The user opened the local page and asked to continue; subsequent connection attempts still timed out. No alternative browser control was used to bypass the approval system.

Consequently these V2.1 checks are NOT marked passed:

- Rendered layouts and horizontal overflow at 360, 390, 768, 1024 and 1440px.
- Actual pipe/row interactions and junction highlighting.
- All deliverable, format, dimension and journey tab switches, including keyboard navigation.
- CTA scroll positioning, generated draft contents in a real email client, clipboard transfer, mobile menu and FAQ interaction.
- Reduced-motion emulation and final console errors.

Responsive rules are implemented, including horizontal scrolling contained within labelled table regions, larger mobile diagram hit areas and stacked contact fields. They still require visual verification. No new V2.1 screenshot is claimed; existing V2 screenshots in `qa/` predate this refinement and must not be used as V2.1 evidence.

Suggested browser acceptance: select each pipe through both representations; switch all three deliverables and both formats; inspect all five customisation dimensions; use Arrow keys/Home/End in every tab group; fill an optional topic and description and inspect the decoded mailto; test copying, FAQ and mobile menu; check privacy and legacy paths; inspect console and overflow at each required width.
